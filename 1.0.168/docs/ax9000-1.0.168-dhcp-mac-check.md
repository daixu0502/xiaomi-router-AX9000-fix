# AX9000 1.0.168 的 DHCP 与 WAN MAC 问题核对

日期：2026-10-26。对比用户提供的原厂开发版 1.0.140 与稳定版 1.0.168，未部署修复、未修改实际 DHCP/网络配置、未重启服务或设备。

## 结论

| 已知问题 | 1.0.168 结果 |
| --- | --- |
| DHCP 七参数调用九参数工具，造成租期/网关/DNS 错位 | 已修正为九参数；隔离保存、读取和连续保存检查通过 |
| `/16` DHCP 地址池计数反向减法 | 仍存在；正确应为 217 的范围被写成 `limit=-215` |
| WAN 模板在访问者 MAC 查询为 nil 时 HTTP 500 | 仍存在；原模板没有空值保护 |

“MAC 问题”在本文指仓库已确认的 WAN 页面访问者 MAC 空值问题，不是物理网口 MAC 丢失或 WAN 克隆 MAC 错误。

## 核对方法和边界

1. 从两份原厂 ROM 解出的文件作为输入，比较模板与文件摘要。
2. 使用当前 1.0.140 路由器自带的厂商 Lua 编译器，反汇编两版对应字节码。仅解析，不执行编译后的函数；临时输入文件自动清理。
3. 将两版 DHCP 模块加载到独立原厂 Lua 进程，先降权至 UID/GID 65534，再以完全替代的依赖执行待测函数。UCI 写入只落到内存表；DNS 服务重启、设备重启均替换为计数函数；文件访问、外部命令和额外模块加载被阻断。
4. 在电脑临时目录中以 1.0.168 WAN 原模板运行现有 MAC 补丁测试，8 项通过，包括精确修改、备份恢复、重复安装及拒绝覆盖其他改动。

这证明了 1.0.168 所带代码的对应行为，尚未在实际运行 1.0.168 的浏览器页面上做端到端回归。没有通过真实页面保存触发网络修改。

## DHCP 参数错位已经修复

两版工具函数 `setLanDHCPService` 都要求：

```text
start, end, startip, endip, leasetime, ignore, router, dns1, dns2
```

向控制器提交 `/24` 请求：地址范围 5–254、租期 `720m`、网关 `10.31.0.2`、DNS `1.1.1.1` / `8.8.8.8`。

- 1.0.140 控制器传 7 个参数，实际写入租期为 `10.31.0.2`、router 为 `8.8.8.8`、DNS 为 nil，复现原问题。
- 1.0.168 控制器传 9 个参数，两个完整 IP 位置为 nil，实际保存 `start=5`、`limit=250`、`leasetime=720m`，网关和 DNS 均在正确位置。
- 1.0.168 读回租期和 DNS 正常；在同一内存配置上连续提交 10–240、`480m`、清空网关/DNS，返回成功并保存 `start=10`、`limit=231`、`leasetime=480m`。

## `/16` 地址池错误仍在

输入 `10.31.1.50` 至 `10.31.2.10`，正确数量是：

```text
(2 - 1) * 256 + (10 - 50) + 1 = 217
```

1.0.168 工具函数仍按反向差值计算，得到：

```text
(1 - 2) * 256 + (50 - 10) + 1 = -215
```

隔离实测返回 `code=0`，但内存配置中的 `limit=-215`，即接口没有报错却生成了不合理数量。同例中原 `start=5` 也未更新为与 `10.31.1.50` 相符的偏移 306；稳定版不能据此视为完整支持跨第三段的 `/16` 地址池保存。

## WAN MAC 空值问题仍在

稳定版 `/usr/lib/lua/luci/view/web/setting/wan.htm` 第 8 行仍为：

```lua
local mac = string.upper(luci.sys.net.ip4mac(remote_addr))
```

当 ARP 查询无法得到访问者 MAC 时，查询结果为 nil，`string.upper(nil)` 报错。反向代理、跨网段访问或部分端口转发入口可能触发该条件；不表示所有转发访问都会失败。两版 `luci/sys.lua` 的摘要相同。

现有补丁增加 `or ""` 后的表达式仍适用于稳定版原模板，电脑隔离的 8 项检查通过。没有改写 MAC 地址、网络规则或固件原文件。

## 现有补丁的适用结论

- `web-wan-mac/fix-router-web-mac.sh`：能够匹配并修复本次 1.0.168 模板，已离线验证；部署后仍需复查原访问入口。
- `web-dhcp/fix-router-dhcp-web.sh`：其固定摘要对应 1.0.140；对 1.0.168 会拒绝修改。不要仅替换摘要强行套用。常规 `/24` 参数错位已经修复；若需 `/16`，应针对 1.0.168 单独适配剩余问题，保留新版控制器其他改动。
